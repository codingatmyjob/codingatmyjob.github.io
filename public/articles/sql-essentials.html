October 10, 2026

SQL can look like a lot at first, but I find most everyday queries are built from a small set of familiar pieces. This is a quick tour of the ones I reach for most, using a simple users table for examples. Swap in the table and column names from your own database.

Start with a SELECT

-- Select only the columns you need
SELECT username, email
FROM users;

-- Filter, sort, and limit results
SELECT username, created_at
FROM users
WHERE active = TRUE
ORDER BY created_at DESC
LIMIT 10;
  • I name the columns I need instead of reaching for *; it keeps the result focused and makes it easier to see what the query is doing.
  • WHERE filters the rows. Combine conditions with AND or OR, and use operators like =, <>, >, and <.
  • ORDER BY sorts the result; add DESC to reverse the order. I use a row limit while exploring so a query doesn't return more than I need.
  • One small SQL surprise: missing values need IS NULL or IS NOT NULL. Comparing with = NULL won't work as expected.
  • The example uses LIMIT, supported by PostgreSQL, MySQL, and SQLite. SQL Server commonly uses TOP or OFFSET ... FETCH instead.

Combine and Summarize Rows

-- Join matching rows from two tables
SELECT users.username, orders.total
FROM users
JOIN orders ON orders.user_id = users.id;

-- Count rows by status
SELECT status, COUNT(*) AS order_count
FROM orders
GROUP BY status
HAVING COUNT(*) > 1;
  • I use a JOIN when the information I need lives across related tables. Here, each order's user_id matches a user's id.
  • Use LEFT JOIN when you want every row from the first table, including rows with no match in the second.
  • COUNT, SUM, and AVG summarize values. GROUP BY makes one summary per group, and HAVING filters those groups.
  • AS gives the result column a name that's easier to read.

Add and Change Data

-- Add a row, listing the target columns
INSERT INTO users (username, email, active)
VALUES ('alex', 'alex@example.com', TRUE);

-- Change selected rows
UPDATE users
SET email = 'alex.new@example.com'
WHERE username = 'alex';

-- Remove selected rows
DELETE FROM users
WHERE username = 'alex';
  • INSERT adds a row. Listing the target columns makes it clear which value goes where.
  • UPDATE changes matching rows, while DELETE removes them. In both cases, WHERE is what keeps the change scoped to the rows you intended.
  • Before I run either one, I double-check that condition. Without WHERE, every row in the table is changed or removed.

Transactions

BEGIN;

UPDATE accounts
SET balance = balance - 25
WHERE id = 1;

UPDATE accounts
SET balance = balance + 25
WHERE id = 2;

COMMIT;
-- Use ROLLBACK instead of COMMIT to cancel the transaction

Transactions let me treat a few related changes as one unit: either commit them together or roll them back. That is useful for work like transferring money, where both sides need to update. Check how your database client handles transactions; some tools commit statements automatically.

Create a Table

CREATE TABLE tasks (
    id INTEGER PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    done BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP
);

I use CREATE TABLE to define the columns and the kinds of values they can hold. PRIMARY KEY identifies each row, NOT NULL requires a value, and DEFAULT fills one in when an insert leaves it out. Types and auto-generated key syntax differ between databases, so check the docs for the one you're using.
